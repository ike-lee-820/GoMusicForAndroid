# GoMusic 26.11.22 更新说明

- 版本：26.11.22（versionCode 124，可直接覆盖安装 26.11.21）
- 日期：2026-11-14
- 适用：Android 手机端；桌面端已停止开发
- 版本号按 `年.月.该月版本` 顺延。本文件同时作为 GitHub Release 正文与应用内「更新说明」全文。

---

## 一、录制步骤改为三段式生成

录制入口打开后，**先识别可用音质**：网易云歌曲用 `Netease.availableLevels()` 逐档探测，只有服务端返回的音质名与发送档位一致才记为可用；本曲已下载的严格同档位文件、本站详情里能映射到档位的音频也会并入。识别完成前不展示音质按钮，完成后「音质」一栏**只显示可用档位**，当前选择不在结果里时自动切到最高可用档位，避免把没有的档位显示成有。

生成流程按用户要求拆成三段，前台服务通知与「设置 → 录制列表」同步显示阶段、详细文字和百分比：

| 阶段 | 进度 | 内容 |
| --- | --- | --- |
| 步骤 1/3 · 下载素材 | 0–30% | 下载所选音质的音频与 `/lyric` 歌词；音频下载按字节刷新 KB 进度，歌词写入缓存并解析 LRC / `tlyric` |
| 步骤 2/3 · 音频处理 | 30–55% | 「原声」不重编码，直接搬运压缩样本；选择「减弱人声」时按强度做 PCM 中置抵消、AAC 编码，并显示解码 / DSP / 编码阶段 |
| 步骤 3/3 · 录制视频 | 55–100% | 配置 AVC 编码器、逐帧绘制、写入视频轨与音频轨，显示当前帧 / 总帧数 |

音频首样本与视频首帧都统一映射到虚拟时间轴 `0`：`MediaExtractor` 的第一个音频 PTS 被减去，视频第一帧 PTS 从 `0` 开始，通知与日志明确写出「开头歌曲和视频对齐」。成品时长继续以音频真实时长为准，不再用播放器里的估算 `durationMs`。

## 二、预览只取时长一半那一帧

录制页不再提供 `−5s / +5s / 回到当前`。预览固定渲染 `duration / 2` 的那一帧，标题写明「预览：仅显示时长一半 mm:ss / 总时长」。这样配置字号、字体、译文、偏移、样式时所见即所得，又不会让预览拖动影响正式生成。

预览仍按所选比例 `fit` 居中，最多占屏高 34% 且不超过 240dp，9:16 / 横屏 16:9 都不会占满整页。预览与正式编码继续调用同一个 `renderRecFrame()`。

## 三、录制页实时显示后台生成进度

录制页读取 `RecorderHistory` 的当前「进行中」记录，显示进度条、阶段名、百分比和详细文字；退到后台后前台服务通知继续显示同样内容。「录制列表」的进行中卡片也增加阶段与详情两行，历史记录新增 `stage / detail` 字段并带默认值，旧记录可正常反序列化。

## 四、字体来源与可变字重

`RecorderConfig` 新增 `fontMode` 与 `fontWeight`：

| 字体来源 | 行为 |
| --- | --- |
| 系统默认 | 使用系统 `Typeface.DEFAULT`，不设置可变轴 |
| 思源宋体 | 使用应用内置、构建时由字体分片合并出的 `R.font.song` |
| 导入 | 读取私有目录里导入的 ttf / otf，未导入时回退系统字体 |

选择「思源宋体」或「导入」后出现「可变字重」步进，范围沿用应用全局字重 `250–900`。录制渲染器所有文字 Paint 统一走 `recTextPaint()`：内置思源宋体与导入的可变字体通过 `wght` 轴设置字重；不支持可变轴的字体由系统忽略该设置。导入字体文件、清除字体、重置为系统默认都保留。

## 五、音质严格一致与素材下载

步骤 1 不再复用播放器缓存或 UI 里提前准备的音频：

- `RecorderFlow.downloadExactAudio()` 只接受同档位的本地下载记录，或 `Netease.audioExactLevel()` 返回的严格同档位地址；服务端降档、无地址、文件过小都直接失败，不偷偷换成别的档位。
- 歌词走免登录快速通道 `/lyric?id=...`，原始 LRC 与 `tlyric` 都写入缓存。自定义 LRC 仍可覆盖原歌词，译文按时间轴对齐。
- 「原声」仍把步骤 1 下载的压缩音频样本原封不动写进 MP4，不解码、不重编码；只有「减弱人声」才解码后处理。

## 六、其余功能保持不变

26.11.21 的圆盘＝横屏播放器圆弧歌词、进入录制页无条件暂停并服务层兜底、退出按进入前状态恢复；26.11.20 的录制列表、离屏快编码、严格音质、选项一致；26.11.19 的两种样式、比例 / 分辨率 / 帧率 / 码率、歌词大小 / 偏移 / 改词 / 译文、后台通知；以及 3D 环绕、均衡器、自动续播、更新说明 Markdown 全文等全部保留。

## 七、验证

1. 打开播放器「录制视频」：显示「正在识别可用音质…」，完成后音质栏只有可用档位，且当前档位在其中
2. 预览固定显示歌曲时长一半的画面，不再有 −5s / +5s / 回到当前按钮
3. 字体可选系统默认 / 思源宋体 / 导入；后两者出现可变字重，调整后预览和成品都生效
4. 点「开始生成」：通知、录制页、录制列表都依次显示「下载素材 → 音频处理 → 录制视频」，含 KB、帧数和百分比
5. 原声成品音质与所选档位一致；成品开头音频与视频都从 0 对齐，不会先出声或先出画面
6. 设置 → 检查更新 → 查看更新说明，能看到本文完整 Markdown，关网仍完整

## 八、限制

- 无法做实机画面与听感验收；编码、字体可变轴、通知刷新以代码与 CI 构建结果为准
- 识别可用音质会逐档请求一次 `/song/url/v1`；网络异常时只把已下载同档位文件计入可用列表，未探明的档位不会显示成有
- 导入字体若不是可变字体，`wght` 设置不会改变粗细；这是字体本身限制
- 减弱人声仍是纯信号处理的中置抵消近似伴奏，不是 AI 分离，复杂古典 / 自由爵士效果有限
- Activity 被系统回收（非正常退出录制页）时不会触发恢复播放
