## 一、歌词请求太慢

用户给的接口：`https://mapi.myocd.de5.net/lyric?id=33894312`，**不需要登录**，标准响应里 `lrc.lyric` 就是主 LRC 歌词。

代码里其实早就在调 `/lyric`，但它走的是通用 `getOnce()` / `get()`，慢在四处叠加：

| 开销 | 之前 | 现在 |
| --- | --- | --- |
| URL 参数 | 强制追加 `unblock=true`、`randomCNIP=true`、`timestamp` | 只有 `id` |
| 登录态 | 把清洗后的整串 cookie 拼进 URL（接近 4KB） | 完全不带，免登录 |
| 失败处理 | 退回 `get()` 重试 2 次并 `sleep(300/700ms)` | 单次请求，不重试不等待 |
| 切歌顺序 | 歌词排在 `/song/detail` 之后串行发 | 与详情并发，先出歌词 |

**改动 1｜独立快速通道**：`Netease.lyric()` 直接发 `/lyric?id=<id>`，用复用连接池的 `urlClient` 单次往返，按 `lrc.lyric` 取词。只有主请求为空才补一次 `?id=..&randomCNIP=true`（境外 IP 的 460 兜底），这次同样不带 cookie、不带 unblock、不重试。其余网易云接口「强制 randomCNIP」的全局规则不变——这是专给免登录歌词开的快速通道。

**改动 2｜歌词不再等详情**：`MainViewModel.onItem()` 里 `/song/detail`（补封面、专辑、歌手）原来和歌词挤在同一个协程、顺序执行，详情一慢歌词就跟着干等。现在详情单独跑一个任务，歌词只管自己那条链；两者都用 `curSsid == id` 兜底，切歌不会串数据。歌词超时（8s）、本地歌词兜底、点「暂无歌词」重试全部保留。

接口返回的 `tlyric` / `romalrc` 暂不接管应用内的 AI 翻译链路，避免改动译文合并逻辑；本版只解决「歌词来得慢」。

## 二、竖屏播放器没有 3D 环绕

`SurroundIconButton` 之前只放在横屏展开控制栏的第一行，竖屏 `PlayerBody` 的功能键行只有均衡器，没有环绕入口——弹层本身与横竖屏无关，所以竖屏不是「打不开」，是根本没有按钮。

现在竖屏功能键行在均衡器后面补上同一个环绕按钮（24dp 网格、1.7 笔触，与 MV / 均衡器同规格），开启时图标显示主题主色。点开就是 `SurroundSheet`，和横屏完全一致。

## 三、3D 环绕界面没有边距

`SurroundSheet` 的 `Column(Modifier.fillMaxWidth())` 直接铺满容器，标题、开关、强度按钮全贴屏幕边缘。现在按均衡器面板的规格加边距：

- 横向 20dp、纵向 12dp，`navigationBarsPadding()` 避开底部导航栏
- 整块 `verticalScroll`，小屏或大字号能滚到底
- 末尾补 10dp 余量，最后一行说明不贴底

开关、强度三档、DSP 参数（150Hz 以下不空间化、软限幅）一行没动，纯排版。

## 四、之前的机制保持不变

- `release.yml` 发布时读 `docs/release-notes/<版本号>.md` 作 Release 正文；归档 `docs/release-notes/26.11.17.md` 与根目录 `RELEASE_NOTES.md` 内容一致，就是本文
- 应用内「更新说明」按 Markdown 排版，加速/直连取最完整候选，断网读 Release `body` 全文
- 26.11.15 的「暂无歌词」点击重试、26.11.16 的文案截断修复、3D 环绕独立 DSP、自动续播服务层兜底、音质逐档回退、均衡器、后台保活、封面高清、验证码登录风控提示均未改动
- 代理仍是 v6.gh-proxy.com，失败回退直连

## 六、限制

- 你贴的两个歌词链接解析服务都返回失败，不过接口说明与完整响应示例已在消息正文里给全，实现依此对齐，未依赖解析结果
- 我无法做实机手势与视觉验收，边距和竖屏排布以代码与 CI 构建结果为准；日志里可核对歌词请求 URL 与耗时
- 若服务端对不带 cookie 的 `/lyric` 返回 460，会自动补发一次带 `randomCNIP` 的请求；仍为空则按「暂无歌词」处理，可点击重试
