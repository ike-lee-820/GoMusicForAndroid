# GoMusic 26.11.23 更新说明

版本：26.11.23（versionCode 125，可直接覆盖 26.11.22）
主题：修复后台录制白屏 / 中断，以及「减弱人声」不生效

这版只动录制链路，播放器、均衡器、3D 环绕、更新说明页面等功能均未改动。
两个问题都在真实源码里定位到了具体位置，不是参数微调。

## 一、后台录制白屏、无法继续

### 1. 熄屏后 CPU 被挂起

`RecorderService` 声明了 `WAKE_LOCK` 权限，但代码里从来没有 `acquire()`。
退到后台或熄屏后系统可以让 CPU 休眠，编码循环停住、通知卡在某个百分比，
回到前台看到的就是停在白屏且再也不动。

现在服务启动时持有 `PARTIAL_WAKE_LOCK`（上限 1 小时），任务结束、取消、
服务销毁三处都会释放。日志新增「录制服务：已持有 CPU 唤醒锁」。

### 2. 硬件 Canvas 在后台画白帧

`drawFrame()` 用的是 `lockHardwareCanvas()`。它依赖 GPU，熄屏 / 后台时 GPU
可能被挂起，会抛异常或直接提交空白帧——这正是成品白屏最直接的来源，
且异常没有被捕获，整条任务会直接失败。

现在优先用 CPU 软件 `lockCanvas(null)`，失败才回退硬件路径，最多重试 3 次；
单帧连续失败时把帧号和原因写进日志与录制列表，不再只显示一个笼统的「失败」。

### 3. 视频轨缺 SPS/PPS

编码器在 2 秒内没有回调 `INFO_OUTPUT_FORMAT_CHANGED` 时，旧兜底直接
`muxer.addTrack(vfmt)`。`vfmt` 是 configure 时传进去的格式，**不含 SPS/PPS**，
写出来的 MP4 视频轨没有编解码配置，很多播放器直接显示白屏或无法解码。

现在：等待上限放宽到 6 秒并持续补帧促使编码器回调；万一仍要走兜底，
改用 `vcodec.outputFormat`（运行时实际格式），拿不到就明确报错，
绝不写一条缺 csd 的轨。日志新增「已用运行时输出格式启动 muxer」。

### 4. 服务被回收后任务凭空消失

`RecorderJobHolder.pending` 是内存单例，`START_STICKY` 重启时 intent 为 null、
pending 也没了，旧版直接 `stopSelf()`，任务就没了。

新增 `RecorderJobStore`：提交时把配置与歌曲标识写成最小快照，服务重启后
从快照重建任务、复用「进行中」那条历史记录（不再重复插入一条），
重新准备音频与歌词后继续跑。任务完成 / 取消 / 失败都会清除快照。
日志新增「服务被回收后重启，已从快照恢复任务」。

另外 `startForeground()` 与 `startForegroundService()` 都加了异常兜底，
Android 14+ 偶发的前台服务限制不再变成一次无声失败。

## 二、减弱人声无效

### 1. 编码器输入 PCM 字节序颠倒

`enc.getInputBuffer()` 返回 direct `ByteBuffer`，默认是 BIG_ENDIAN；
旧代码直接 `asShortBuffer().put(...)`，写进去的 16bit PCM 高低字节反了。
解码 → DSP → AAC 这条链因此输出不对，听感上就是「处理没生效 / 一团糊」。
现在显式 `ib.order(ByteOrder.LITTLE_ENDIAN)` 后再写。

### 2. 按容器头而不是解码器输出解析 PCM

旧代码用 `inFmt` 的 `ch` 去切 PCM 帧。`inFmt` 是压缩文件的声道数，
遇到 SBR/PS、float PCM、24bit 等音源，解码器实际输出格式与它不一致，
左右声道会错位，中置抵消自然算不出来。

现在从 `dec.outputFormat` 读取真实的采样率、声道数、`pcm-encoding`：
float PCM 先转成 16bit，AAC 编码与 PTS 计算都用真实的 `outSr / outCh`。

### 3. 单声道音源直接返回原样

`VocalReduce.process()` 里有一行 `if (channels < 2) return pcm`。只要音源是
单声道，「减弱人声」就完全不生效且没有任何提示。

现在单声道走一阶低通拆中频、按强度衰减 300Hz 以上人声主要能量的近似路径；
双声道改用标准 karaoke 矩阵 `L-k·R / R-k·L`，100% 时中置人声被抵消，
低频单独回补，避免鼓与贝斯一起消失。默认强度从 75% 提到 85%。

### 4. AAC 尾部样本被漏掉

`drainEnc()` 原来是非阻塞的 `dequeueOutputBuffer(0L)`，编码器最后几帧
可能还没就绪就结束循环。现在末尾用 20ms 超时循环 drain 到 EOS，
并记录「DSP 后 AAC 样本=N 段，EOS=true」。

### 5. 人声模式误判与可验证性

`vocalMode` 匹配放宽到兼容旧配置里的英文值，避免被当成「原声」。
新增逐项日志：人声模式与强度、解码输出格式、「人声处理生效：首块 RMS
a -> b」，能直接确认 DSP 是否真的跑过，而不是靠听感猜。

## 三、验证方式

- 选「减弱人声」生成一次，日志里应出现
  `录制音频：解码输出 sr=.. ch=.. pcmEnc=..`、
  `人声处理生效：.. 首块 RMS .. -> ..`、
  `录制音频：DSP 后 AAC 样本=.. 段，EOS=true`；
  强度 100% 时人声应明显后退、鼓与贝斯仍在。
- 开始生成后立刻熄屏 / 切到别的应用，通知应持续推进到 100%，
  回到应用后录制列表显示「已完成」，成品第一帧不是白屏。
- 若仍失败，录制列表的「详情」会写明具体帧号或阶段，把那行发来即可定位。

## 四、如实说明

- 沙盒没有 Android SDK / Gradle（Java 11，需 17），**无法本地编译与实机验收**；
  本次改动由 CI 编译、签名校验、发布三步验证，画面与听感以实机为准。
- 中置抵消是纯信号处理，不是 AI 分离：人声不可能被完全抹掉，
  复杂古典、自由爵士、单声道老录音效果有限。
- 这轮附带的 83 个资源解析全部失败，没有据此改写任何接口或渲染逻辑。
