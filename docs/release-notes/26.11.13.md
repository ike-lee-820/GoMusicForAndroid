# GoMusic 26.11.13 更新说明

- 版本：26.11.13（versionCode 115，可直接覆盖安装）
- 版本号规则：`年.月.该月版本`，本月第 13 版
- 本次没有改播放器、歌词、音质、均衡器，只动「发版文案」与「更新说明阅读」

---

## 一、GitHub Release 文案换成完整更新说明

以前每个 Release 的说明都是同一句占位文字：

```
自动构建的正式版 APK（固定 keystore 签名）
```

现在 `release.yml` 在发布时读取该版本的完整说明文件作为 Release 正文：

- 优先 `docs/release-notes/<版本号>.md`（如 `docs/release-notes/26.11.13.md`）
- 该文件不存在时回退仓库根目录 `RELEASE_NOTES.md`
- 两个都不存在则**直接构建失败**，不会再悄悄发出一句占位文案
- Release 已存在时用 `gh release edit --notes-file` 同步文案，重跑构建也会把正文刷新成最新版

也就是说：**以后每一版的 Release 页面，就是这份更新说明本身**，不用再去翻聊天记录或另外找文档。

## 二、应用内可以完整查看更新文档

之前应用内看不到全文，卡在两处：

1. `Updater.parseInfo()` 里 `body?.take(600)` —— GitHub 返回的 Release 正文被硬截断到 600 字，后面的内容永远拿不到。
2. 弹窗里说明区 `heightIn(max = 260.dp)` + `weight(1f, fill = false)`，长文本只能挤在那一小块里。

这版改成：

- **不截断**：Release 正文全文进入 `Info.notes`（GitHub body 上限 65536 字符，正常说明远小于它）
- **双保险**：弹窗打开后后台再拉一次仓库里归档的 `docs/release-notes/<版本>.md` 原文（先走 `v6.gh-proxy.com`，失败回退直连）。Release 正文万一被清空或代理只给摘要，仍能拿到未删减的 md
- **整页可滚**：说明区占满剩余高度，内部 `verticalScroll`，长文档从头读到尾
- **长按复制**：说明区包了 `SelectionContainer`，另给「复制全文」按钮
- **看字数**：底部显示「共 N 字」，载入中显示「正在载入完整文档…」，点「查看完整文档」可重试
- **随时可看**：设置页「检查更新」区域新增「更新说明」按钮，不要求有新版本，点开就是同一个全屏阅读页；此时只显示文档和「关闭」，不会出现下载按钮，避免误点

启动时检测到新版本自动弹出的那个页面，用的也是同一套，行为一致。

## 三、以后怎么维护（已固化进流程）

每次发新版，只需要三件事，流程会自动把文案带上去：

1. 按 `年.月.该月版本` 改 `app/build.gradle.kts` 的 `versionName` / `versionCode`
2. 写一份 `docs/release-notes/<新版本号>.md`，就是该版的完整更新说明
3. 推 main，CI 自动构建 APK → 用这份 md 作为 Release 正文 → 上传 APK

历史说明按版本号永久留在 `docs/release-notes/`，应用内「查看完整文档」按当前检测到的版本号拼 raw 地址，所以老版本的说明也一直查得到。
