## 本次改动：某一音质请求失败就自动更换上一音质

按 `NM_LEVELS` 从低到高的顺序，从当前档位起**逐档往回退一档**（更低一档）：

```
jymaster → vivid → dolby → jyeffect → hires → lossless → exhigh → higher → standard
```

之前只走 `levels(quality)` 的 4 个老档位：手动选了 `jymaster` 取不到时直接跳到
`lossless`/`standard`，中间明明能播的档位全被跳过。现在一档一档退，失败才换。

- 判定为「这一档失败」：网络异常、HTTP 非 200、业务码异常、返回地址为空。
  每档失败写一行日志并自动更换上一音质，直到拿到可用地址或到 `standard`。
- 命中风控（`-462` 易盾验证 / `10004` 安全风险 / 401 需登录 / 460）立即终止，
  不再把 9 个档位各打一遍；这类错误换任何音质都拿不到地址。
- 档内两个参数变体（基础 + `realIP`）并发，档与档之间串行；保留
  `/song/url/match` 解灰匹配与游客 cookie 兜底。
- 服务端降档返回时，实际档位仍以返回的 `level` 为准，不会把低音质地址标成 Hi-Res。
- 音源缓存改为连「实际档位」一起存：命中缓存时不再拿请求档位冒充实际档位，
  下载记录、文件名、离线播放判断的档位都是真的。

## 验证

播放一首高音质档位取不到的歌，`设置 → 查看日志` 里应能看到：

```
开始取播放地址 id=... 起始档位=jymaster 降档链=jymaster→vivid→...→standard
音质 jymaster 请求失败，自动更换为上一音质 vivid
拿到地址（vivid）：https://...
```

命中风控时是 `音质 xxx 命中风控/需登录，停止逐档降档（code=...）`。

## 两点说明

1. 只改**本次播放/下载**实际使用的档位，不改动全局音质设置 —— 否则一首歌没有
   高音质就会把整个曲库都降成标准。音质菜单里仍高亮你选的档位。
2. 核对仓库时确认：`main` 与 Releases 实际停在 **26.11.9**；此前口头说过的
   26.11.10（3D 环绕）和 26.11.11（均衡器/设置独立页面）并没有推上 main，
   仓库里没有对应代码。本版基于真实主线 26.11.9 修改，版本号跳到 26.11.12
   以免与既有说法冲突。那两版功能本版不含，需要补做可另行安排。
