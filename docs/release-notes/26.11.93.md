# GoMusic 26.11.93

## ① 三点动画重做

上一版前奏 / 间奏的三点太占纵向空间、居中、还是主色→灰的「由亮变暗」，和反馈对不上。现在：

- **左对齐**：与歌词正文同一个 8dp 起始内边距，不再居中
- **压缩纵向**：原来上下各 46dp 的 padding（撑开 90dp+），改成固定 14~22dp 的小高度容器；点缩到 7dp，间距只随动画微调 8dp，整行不再把歌词列表顶开
- **灰 → 黑**：三点从左到右逐个由 `muted` 灰变成文字色（亮色主题即纯黑，深色主题自动为白），0.72 之后三点全部到黑，再一起淡出、间距收回，接下一句
- 触发条件不变：单句恰好 `Music`（M 大写）且后面还有歌词；尾奏仍整行移除、不高亮不滚动

## ② 切到下一首歌定位不到第一句

根因是两处叠加：

- `initialIndex = w.activeIndex(vm.positionMs)` 用的是**切歌瞬间还停留在上一首末尾**的 `positionMs`（播放器收起时轮询 1 秒才更新，甚至不更新），对新歌词会算出「最后一句」，列表从末尾开始
- 滚动状态拿 `WordLyric` 对象本身当 `key`，data class 相等时不会触发重建

现在：

- VM 暴露 `wordLyricSsid`，歌词列表按**歌曲 id** 重建 `LazyListState`，固定从歌词第一行落位
- 新歌词的第一次跟随循环直接落位第一句，不拿任何可能仍旧的位置去算 `activeIndex`，避免又被滚到最后一句
- 逐字与行级歌词都直接读播放器真实位置，不再吃 250ms 轮询的 `vm.positionMs`；切歌后它立刻是新歌的 0
- 同一首歌在封面页 / 歌词页之间切换时 state 不重建，仍停在正在唱的那句，不受影响

上版的「行级歌词滚动完成才高亮」「60ms 检测 + 360ms 动画」「尾奏停滚」全部保留。
