修复
- 歌曲加载慢：预取后两首的音源地址虽然声称走「独立客户端」，实际仍调用播放解析共用的那个 OkHttp 客户端。预取一跑就是两三条降档链，正在解析的当前歌曲被挤到队尾。
- 歌曲加载慢：音质档位一档一档串行请求，选了高音质而歌曲只有较低档时，要连等好几个 HTTP 往返才降到底；单次请求超时最长 7 秒，整条链最多 8 秒。
- 歌词加载失败无法重试：歌词页「暂无歌词」只是静态文字，没有任何点击入口；重试函数还会被残留的加载中状态直接挡掉。
- 歌词加载失败无法重试：预取层把「新接口失败、老接口也空」的结果照样写进缓存，重试时直接把那份空结果还回来，永远不会重新发请求。

新增
- 预取音源、歌词、音质探测分别走独立的调度池与连接池，与播放解析物理隔开；播放解析不再被后台预热抢占连接。
- 取地址改为前 3 档与 standard 并发探测，一次往返即可拿到结果，再严格按音质从高到低选取命中档位，不会为了快而跳过中间档位导致音质标错；剩余档位才串行补探。
- 播放地址请求超时收紧到连接 2 秒 / 单次 4 秒，整条链 6 秒截止；在途去重等待上限同步收窄；取不到地址的负缓存从 30 秒缩到 8 秒，失败后可更快重试。
- 歌词页空态整块可点击重试，加载中显示「正在加载歌词…」，失败时明确给出「点击重试」。
- 重试时强制取消残留任务、清空已加载与在途标记，并清掉该歌曲的歌词缓存，重新走完整的「新逐字接口 → 老歌词接口 → 本地歌词」回退链；本地音频重试会重读文件标签。
- 空歌词结果不再写入缓存，避免一次失败后永久拿不到歌词。
