# 更新说明归档规则

- 每发一版，放一份 `docs/release-notes/<版本号>.md`，文件名与 `versionName` 一致，例如 `26.11.13.md`。
- 这份 md 就是该版 GitHub Release 的正文，也是应用内「查看完整文档」拉取的原文。
- 命名规律：`年.月.该月版本`（例：本月第 13 版 = `26.11.13`）。
- 根目录 `RELEASE_NOTES.md` 是回退文案：某版没有归档 md 时，CI 用它当 Release 正文。
  建议每次发版顺手同步成最新版说明，避免回退到过期内容。
- 两者都缺失时，发布流程直接失败，不允许再发出占位文字。
- 归档只增不改：历史版本的说明按版本号永久保留，老版本在应用内仍可查到。
