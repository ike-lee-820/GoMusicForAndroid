# GoMusic 26.11.91

## ① 私信分享专辑/歌单不再把封面图片链接印在气泡里

根因：网易云资源私信的 `msg` 是一整段 JSON，里面塞满 `picUrl` / `coverUrl` 等封面地址。旧版气泡会把「正文里没出现的链接」逐条列出来，于是发一张专辑，下面跟着一串 `p1.music.126.net/...jpg?param=`；解析没取到名字时更会把整段 JSON 当正文，链接还被画成可点下划线。

- 资源消息解析失败时不再回退整段 JSON，改成「分享的资源」；会话列表的最后一条同样清洗
- 新增图片 CDN 判定（`music.126.net` / `nosdn.127.net` / `/obj/` / 图片后缀 / `param=` 缩略参数）：这类地址不画成可点链接、不整条印出来，正文里只留 `[图片]` 占位
- **资源消息**只显示类型标签 + 资源名（💿 专辑：xxx），不再额外列出原文链接；纯文本消息里的普通网页链接仍可点、仍在应用内 WebView 打开
- 资源卡片本身照旧可点开专辑 / 歌单 / 歌曲，「点击打开」提示不变

## ② 歌单「强制全部同步」

之前一直没做到完全同步，是四个坑叠在一起：指纹相同就跳过曲目、云端曲目直接**覆盖**本地（本地后加的歌一同步就没了）、本地歌单只上传 `nm_` 前缀的歌（本站曲库歌全丢）、云端列表拉空时整个同步直接退出。现在：

- **默认强制全量**：按钮改名「强制全部同步」，进应用的静默同步也走全量；指纹不再拦住曲目刷新，红心合并也强制重跑；同步进行中再点一次会排队重跑，不再被静默丢弃
- **双向曲目对账**：每张歌单取「本地 ∪ 云端」并集——本地独有的歌补传云端，云端独有的歌补回本地，两边最终都有全部曲目；曲目集合变了还会用 `/song/order/update` 对齐顺序（只在全部歌曲都能映射到网易云 id 时才发，避免传半份挤掉云端其它歌）
- **本地有、云端没有的歌单 → 云端新建并上传所有歌曲**：`nmId=0` 的歌单 `/playlist/create` 后，把每首歌解析成网易云 id 再分批上传；本站曲库 / 本地音频没有 id 的，按「歌名 + 歌手」轻量搜索映射到同名同歌手的网易云单曲，尽量做到「所有歌曲」都上去；解析结果带缓存，不重复搜
- **分批上传与重试**：`playlistAddBatch` 按 100 首一批、走同步专用客户端不抢播放链路，整批失败再拆半重投，返回真正成功写入的数量。以前一次把整张歌单 id 全拼进 `tracks=`，URL 超长或中间一个 id 不被接受就整批失败，界面还显示「同步完成」
- **云端已删、本地仍在的歌单**重新在云端 create 并回填新 id；云端列表整体拉空时保留黑名单、不误判成「云端已删」，避免在云端刷出一堆重复歌单，同时照样把本地歌单全部上传
- 结果提示改成实打实的数字：新建 / 重建歌单数、补传多少首（几张歌单）、补回本地多少首、未匹配多少首、红心合并与上传数

收藏 / 订阅歌单（`cloudReadOnly`）仍只下载不回写——网易云不允许写别人的歌单，这是接口限制。

## 说明与限制
`mapi.myocd.de5.net` 在沙盒返回 403，云端写接口与私信返回结构**未做实机联调**，以 CI 编译＋签名校验为准。按歌名映射本站歌曲属于模糊匹配，找不到或匹配偏差会计入「未匹配」并明说，不会静默丢歌；本地专属且网易云没有的歌无法凭空变成云端歌曲。云端删掉的歌单本地仍保留（接口偶发漏返回直接删用户歌单代价太大），但本地还在的会重新建回云端。
